## 修：拆章后章节标题/表头换行
用户反馈拆章后"表头"看起来奇怪、换行。排查：标题数据本身是单行（`split_chapters` 用 `line.trim()` 取标题，测试断言 `sample_titles[0] == "卷一 起程"` 验证）。问题在两层：
- 数据层防御：新增 `clean_title()`（折叠所有空白/换行/零宽为单空格 + trim），`split_chapters` 取标题与 `preview_split` 收集命中行时统一走清洗，根绝源文件异常换行导致的多行标题。
- 显示层：正文区顶部章节标题 `<h1>` 无约束会换行撑乱布局 → `layout.css` 加 `nowrap + ellipsis` 并给容器 `.surface-title` 加 `min-width:0`；`ScriptSurface.tsx` 给 `<h1>` 加 `title` 完整标题 tooltip。分段表头标签 `.segment-head > span` 补 `white-space:nowrap` 防标签换行。

附带修复（上一轮拆章工作遗留、仅编译未跑测试）：`is_plausible_split_pattern` 阈值 `matches*5 <= non_empty`（标题≤20%）与自身测试（3 标题/6 行=50%）矛盾，导致 `chapter_split_heuristics_cover_common_formats` 失败。改为 `matches*2 <= non_empty`（≤50%，标题非主体），注释同步。

校验：39 个 Rust 单测全过；`tsc --noEmit` 与 `vite build` 通过。
