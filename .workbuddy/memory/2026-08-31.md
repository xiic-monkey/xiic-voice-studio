# 2026-08-31

## UI 排版审计（未改动代码，仅诊断）

对 src/App.tsx（2517 行）+ App.css（1798 行）做了一轮排版/设计系统审计，产出问题清单：

### P0 布局硬伤
- `.segment-row` 列宽预算 516(固定列) + 50(gap) + 32(padding) + 260(文本列 minmax 下限) = **858px**。
  窗口 1440 时中间列正好 858，文本列被压死在 260 下限；1180 时可用 674 < 需求 750，**溢出 76px**；
  1080（最小窗口）可用 574，**溢出 176px** → 核心表格常年横向滚动。
- `.segment-row` 用 `align-items: stretch`，序号列是裸 `<span>` → 贴顶显示，与同行的
  select/input/textarea 不在同一视觉基线。
- 行内 `textarea { resize: vertical }` 未禁用 → 用户拖动即撑高整行，行高参差。
- `.voice-card` / `.job-card` 被 `.character-card, .voice-card, .job-card { grid-template-columns: 14px 1fr 34px }`
  定义后，又在 676 行被 `.voice-card, .job-card { grid-template-columns: minmax(0,1fr) }` 覆盖成单列 →
  JSX 里的 3 个子元素竖排堆叠，信息密度崩塌。
- `.chapter-item.selected` 与 `.chapter-item.selected .chapter-select` 重复施加
  `background: var(--accent-soft)` + `inset 3px 0 0` → 选中态双层背景、左侧双蓝条。
  且 `.chapter-select` 规则被定义了两次（374 / 420 行）。

### P1 设计系统缺失
- font-weight 出现 680 / 720 / 730 等非标准值：Inter 是可变字体能渲染，PingFang SC 会取整到 700
  → 中英文混排字重不一致。
- 硬编码颜色 20+ 处，其中 `#f8fafc` / `#fbfcfe` / `#fafbfc` / `#f4f7fb` / `#f8fbff` 五个近似浅灰白各用各的。
- 间距无栅格：padding 出现 7/9/11/13 等奇数手调值；gap 2~18 全用。
- 圆角 4/5/6/8/12/20/50% 混用，无层级逻辑。
- 字号 10px（`.audio-time`）在中文下过小。
- `.panel-title` 图标时有时无（项目/角色/声音有，章节/审听/队列无）→ 标题左边缘不齐。
- 三种 hover 风格并存（通用 `#f4f7fb` / toolbar `accent-soft` / voice-center-nav 仅变色）。
- `.segment-row` 无 `:hover` 态、无斑马纹 → 长列表审听容易串行。
- `button.audio-icon-button:first-of-type` 用结构伪类定位播放键，脆弱。
- 五处 `overflow: auto` 容器未定制滚动条、未设 `scrollbar-gutter`。

### P2
- `@media (max-width: 820px)` 是死代码（body min-width 1080，Tauri 窗口 minWidth 1080）。
- 无 `prefers-color-scheme` 深色适配（变量都在 :root，改造成本低）。
- 状态胶囊 `.status` 同时挂 audioStatus + reviewStatus 两个 class，一个色块表达两种语义。

### 结论
老板反馈"UI 排版粗糙、配色还行"——配色确实没问题（蓝 #276ef1 主色 + 语义色完整），
粗糙感主要来自尺寸系统（间距/圆角/字重/列宽）失控，不是色彩问题。
